# 부모용 리포트 루브릭 (제품 오너 확정 기준)

2026-08-20~21 세션에서 오너가 확정한 기준. 부모/아동에게 나가는 모든 산출물(HTML·PDF)은 배포 전 이 8개 항목을 전부 통과해야 한다. 하나라도 실패하면 배포 불가.

| # | 기준 | 통과 판정 | 실패 예 |
|---|---|---|---|
| R1 | **결핍 프레임 금지** — 아이가 "못한다"로 읽히는 표현·그림이 없어야 한다 | 화면 어디에도 0점·최하 밴드·찌그러진 도형·빈 행·"기록 없음" 축 명단이 없다. 미관측 축도 기본 구간 85~88 값과 전향 문구("곧 피어날 힘")로 표시되어 다른 아이 리포트와 나란히 놓아도 "놓쳤다"로 읽히지 않는다 | 중심 붕괴 도형, "증거 더 보기" 밴드, 미관측 축 이름을 나열한 안내 박스 |
| R2 | **측정 보존** — 모두를 칭찬하되 칭찬 지점이 아이마다 달라야 한다 | 대표 강점(1등 축)이 실데이터에서 아이별로 갈린다(전원 동일이면 실패). 축 순위가 원점수 순서와 일치 | 모든 아이가 같은 축 1등, 순위와 원점수 불일치 |
| R3 | **7 에셋 고정** — HAIN7 7축(TA·IN·CO·VE·DE·IT·OW)과 아동용 정의를 변경하지 않는다 | 축 이름·정의·아동 설명이 SKILL.md 원본과 동일. 바꾸는 것은 표시 방식뿐 | 축 통합·삭제·개명 |
| R4 | **논문 근거 표기** — 실존 논문의 검증된 URL만 인용한다 | 모든 URL이 발행 시점에 실제 접속 확인됨. "보고 형식의 근거이며 점수 타당도 검증 아님" 스코프 문구 동반 | 기억으로 쓴 URL, 점수 자체가 검증된 듯한 표현 |
| R5 | **포맷 완전 통일** — 색·그래프·위치·폰트가 어디서 뽑아도 동일하다 | 팔레트는 토큰 고정(violet #6D5DF7 · coral #FF7A62 · lime #E8FFAE), 서체 명시 로드, 레이아웃 그리드 고정. PDF는 폰트 동봉 후에만 통과 | 머신 폰트 fallback으로 줄바꿈 변동, 임의 색 추가 |
| R6 | **또래 비교 제거** — 다른 아이·평균·규준과 비교하지 않는다 | 기준선·평균·백분위가 부모 화면에 없다. 숫자는 발휘도만: 관찰된 축은 90~100(최약=90, 대표 강점=100, 원점수와 순서 일치), 미관측 축은 세션 지문으로 결정되는 기본 구간 85~88(재실행 시 동일값·관측 최저 90 아래 고정·구간 내 차이 무의미). "아이 자신 기준 상대 지수 + 기본 구간" 공시 필수. 85 미만 숫자 금지 | "또래 대비", 기준 링, 85 미만 숫자, 공시 없는 숫자 |
| R7 | **비주얼 꽉 참 + 강점 부각** — 어떤 데이터에서도 그림이 비거나 부족이 도드라지지 않는다 | 7조각 웨지 전부 채워짐(미관측 축도 기본 크기의 채운 웨지, 점선·빈 조각 없음). 대표 강점이 시각적으로 가장 도드라진다. 중심 허브로 붕괴 방지. 배경은 화이트 톤 고정. 세부 인상 기준은 perception-rubric.md를 따른다(페이드·회색화 금지) | 점선/빈 조각, 반투명·회색 처리, 한쪽 쏠림, 다크 배경 |
| R8 | **데이터 부족 시 리포트 미생성** — 억지로 그리지 않는다 | 관측 축 0개(예: 1턴 세션)면 그림·점수 대신 "수업이 짧아 기록이 부족해요" 안내로 대체 | 빈 세션에서 도형 강제 생성 |
| R9 | **타 아동 데이터 격리** — 배치 입력이어도 부모 산출물은 철저히 1아동 | 부모용 HTML/PDF에 다른 아이의 세션·사례·표·분포가 일절 없다. 여러 아이 데이터(Supabase 배치)는 아이별로 분리 처리되어 각자의 리포트만 생성 | "실제 N개 세션" 표, A/B/C 학생 비교, 반 평균 |

## 판정 절차

1. 실제 스풀 세션 전체를 스윕해 R1·R2·R7·R8을 데이터로 확인한다 (`scripts/stress_test_sessions.py` + 실스풀 스윕).
2. 다크·라이트 두 테마에서 렌더를 캡처해 R1·R7을 눈으로 확인한 뒤 배포한다.
3. R4 URL은 발행 때마다 재확인한다.

구현 이력: 도넛 웨지 지오메트리·발휘도(90~100)는 HTML 데모와 `render_pdf`가 동일 사양을 공유한다. PDF는 동봉 폰트(`fonts/NanumGothic-Regular.ttf`, OFL)만 사용하며 시스템 폰트 폴백이 없다(R5). 구 렌더러의 `score or 0` 중심 붕괴는 제거되었고, 관측 0축 세션은 PDF를 거부한다(R8).
